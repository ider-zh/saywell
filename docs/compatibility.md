## Current support boundary

Logo assets are bundled locally. The console and tooltip use static inline SVG; the manifest uses PNGs at standard toolbar/extension sizes, and console favicons use the 32px PNG. Rebuild, reload the existing unpacked extension, and refresh open pages to pick up the artwork while retaining the same extension identity. Toolbar/favicons may remain cached briefly. The tooltip mark makes no host-page image request and requires no change to website permissions or web-accessible resources.

Manifest V3, minimum Chromium 116 for storage/scripting APIs. Translator support is separately feature-detected and requires a much newer eligible browser/runtime. Chrome and Edge can load the same unpacked package. This is not evidence of full Edge editor/AI parity.

## Manual release checklist

Console layout: desktop canvas is capped at 1180px, settings stack into one column at 760px, and mobile navigation moves above content at 600px. Browser coverage checks English/Chinese console layouts at 1440, 768 and 390px without document-level horizontal overflow; section navigation may scroll horizontally on narrow screens. Desktop navigation/section/save controls remain accessible while scrolling. Vocabulary examples and explicitly saved contexts are available through row disclosures. Verify system font scaling and browser zoom on the user's display before store release; console density does not change website tooltip geometry or editor behavior.

Website modes: fresh installs default to blacklist mode, but still require a browser origin grant (one-time all-websites activation or specific origins). Explicit old allowlists migrate to whitelist mode. Settings/popup can switch modes without deleting lists. Translation cards keep Website settings collapsed without a normal-site blacklist badge; expanding shows the hostname, four site defaults and secondary exact-host blacklist actions. A blocked site's shortcut reopens only its local status panel, with no translation request or input snapshot. Inherited wildcard rules link to Settings. Whitelist mode with an empty list allows no processing; blacklist rules remain a higher-priority exclusion in either mode. Automatic scenarios and the actual MV3 localhost integration verify these behaviors.

Console language: dashboard, settings, vocabulary and popup support English and Simplified Chinese. Follow browser is the default; zh/zh-CN/zh-TW/zh-Hant resolve to Simplified Chinese, other locales fall back to English. Browser tests verify manual overrides, reload persistence, cross-page synchronization, unsaved form preservation, unchanged saved vocabulary, localized dynamic counts/accessibility labels, and a 390 px dashboard without horizontal overflow. Native browser permission/validation dialogs follow the browser's own language. Content tooltip translation/provider outputs keep their existing behavior; this update concerns the console UI.

Use a separate browser test profile and synthetic content. Enable the target website explicitly. Authorize each provider separately. Do not use private messages or sensitive drafts in tests.

For every website below:

1. Type Chinese through the real OS IME; pause during composition. Verify no request or tooltip appears before committing.
2. Pause after a complete sentence. Verify engine/mode labels, no editor mutation, and a responsive editor.
3. Edit while a slow request is pending. Verify that the older result never appears.
4. Copy, Apply where offered, Dismiss and manual shortcut; confirm no accidental submit/send. Complex editor Copy fallback must be usable.
5. Type English with LLM off, then with LLM on. Verify no basic translation in the first case and meaningful polishing in the second. Check mixed Chinese/English product names/code/numbers.
6. Open a vocabulary hint, reveal example, save with/without sentence consent and mark known. Verify stored data and export.
7. Compare counters for independent English/Chinese, paste/drop, undo/redo and AI Apply; test midnight and switching websites.
8. Pause suggestions, disable analytics, exclude the site, remove the site grant, revoke provider consent, remove browser host permission, and go offline. Verify processing/collection obey each independent setting.

## Google/Bing webpage translation

Google web and Microsoft Bing web are separate keyless, experimental engines alongside Edge/MyMemory, not the keyed Google Cloud/Azure services. In Settings choose **Enable free translation** for the four presets, or **Connect and test** for one service. Fresh-install Auto prefers local translation, then Google web, Bing web, Edge and MyMemory before configured keyed/self-hosted services. Existing five-engine orders retain their priorities and append the new disabled engines; upgrades/imports never imply new consent. Both engines can be selected in per-host defaults and are included in configuration backups.

Actual disposable Chromium MV3 probes passed zh→en and en→zh for both engines on 2026-10-20. Direct Node Google requests timed out and Bing requests were refused; that transport result did not describe the extension's successful requests. Reachability still depends on the user's network. Defaults are translate.googleapis.com and cn.bing.com. Optional web base URLs support reachable translate.google.com/www.bing.com or compatible local services; changed addresses require reconnecting, and redirects/ungranted-domain failover are not followed.

Google sends text in GET queries; provider/network URL logs may retain it. Bing performs an anonymous page GET followed by a text form POST. Temporary page parameters stay in worker memory only, with no account cookies or page-script execution. Verification/challenge pages stop that engine and allow authorized fallback; no challenge bypass or blind retries. Inputs above 5,000 UTF-16 units (Google) / 1,000 (Bing) are rejected before that engine's network call and can fall through without poisoning health. These limits are adapter bounds, not an unlimited-free or contractual API guarantee. Existing site/consent/grant/Apply protections remain required.

## Provider setup

**Saywell Free AI** is a keyless developer-sponsored Cloudflare profile. New installs prefill its endpoint and fixed Qwen 3.8 27B model, leave consent/enablement off, and default thinking off. Existing saved providers are not replaced. API-key fields are hidden for this profile, the model is read-only, and output is capped at 800 tokens. Click Connect and test to grant its origin and permit text processing; website access remains separate. No global activation occurs when connecting another profile. Free-plan daily exhaustion is shared across the developer account, resets at 08:00 Shanghai time, and shows a bilingual alert while MT stays usable. No account-wide remaining balance is claimed. The public pilot is approximately rate-limited rather than authenticated, can be stopped by the developer, and has no automatic cutoff date. See cloudflare-deployment.md. Real deployed API and actual disposable MV3 connection tests passed; quota exhaustion is mocked, not deliberately induced on the live account.

For an individual LLM or basic provider, use **Connect and test** after entering its configuration. This saves the configuration, permits text processing, requests the endpoint browser grant if necessary, enables the selected LLM and runs a synthetic request. Chromium's first-access permission prompt still requires a user decision. Ordinary Save, provider/profile selection and configuration import do not grant text consent. Connection does not switch global activation or enable other fallback services. Denied permission leaves saved configuration unchanged; changing profile/provider/endpoint during the prompt cancels setup.

**Disable service** stops new text requests, retaining the configuration and stored key; it does not remove the native browser grant or recall requests already sent. An enabled status indicates consent and may coexist with a failed connection test, whose error is shown separately. Use browser extension settings to remove underlying host grants. Imported configurations reconnect through the same single action.

## Configuration backup portability

Settings → Local data & privacy → Configuration backup exports version 2 and accepts versions 1/2 (maximum 1 MiB). Export first saves valid edits and includes global preferences, custom profiles, active selection, UI language and website/tooltip preferences. Built-in Saywell service values are excluded; only profile-ID references are kept. Import uses current app defaults even for old built-in data, while preserving custom endpoints. Keys, consent, key-storage flags and practice/history data remain excluded. Enabled-but-unconnected services show a named reconnect notice; importing does not authorize remote processing. Connect and test restores the chosen service, and keyed providers may need their key entered again.

Import previews the file before explicit replacement or cancellation; there is no merge mode. Replacement includes unsaved form edits and the saved per-host maps. Existing local keys retain their storage choice only when profile ID/provider/exact endpoint still match (basic providers require the same ID/exact endpoint); deleted or changed identities lose their keys. Provider text consent must be renewed after import. Practice data and usage counters remain unchanged.

Browser grants are not portable: only currently granted website scopes are restored unless the user explicitly selects the unchecked option to request missing permissions. Denial aborts import; leaving it unchecked skips missing scopes. Import does not remove native grants that Chromium already holds. Imported blacklist/whitelist policy still applies separately. Refresh open website tabs to apply imported tooltip positions and newly granted site access. Coordinate restoration remains bounded to the current viewport. Unknown fields, credentials in the file, malformed settings and unsupported versions are rejected before writes.

## Known limitations

Tooltip density: use Small/Medium/Large in the tooltip header (Chinese: 小/中/大). Small defaults to 300px; Medium 380px; Large 480px, each reduced to fit narrow windows. Text height, spacing and font size change together. Choices persist per exact hostname (not path/port/protocol), up to 200 hosts, separately from drag position and site routing. Switching size keeps current suggestions/Apply/vocabulary and does not make another translation request. A size-only settings notification does not cancel a pending LLM result. Size is included in configuration backups; importing older backups restores Small unless a size map exists. Chromium fixtures cover all sizes, late LLM, reload, narrow-window clamping and Apply; a real MV3 localhost scenario verifies size-only broadcasts and stored per-host state.

Website defaults: use the tooltip's Website settings to save action, target, existing LLM configuration/MT-only and basic translation engine for an exact hostname. Other fields inherit global settings, including MT fallback, debounce and style. Selecting a disabled/unconsented/missing-key profile does not enable or authorize it; configure it in Settings first. A removed selected profile disables the site's LLM until you choose another or reset; it never silently uses the global provider. New defaults apply on the next input or manual shortcut, and saving removes old Apply results without editing the draft or making a translation request. Up to 300 hostname entries are stored locally; reaching the cap rejects a new entry without evicting prior routing choices. Subdomains are separate; paths, ports and protocols of the same hostname share an entry. Existing credentials, origin grants and blacklist/whitelist policy remain mandatory. Actual Chromium tests cover two-host/profile/MT routing; full authenticated-site/Edge behavior remains part of manual acceptance.

Saywell is the new product name. Reload the existing unpacked extension from the same `dist` directory and refresh open website tabs to update labels while retaining the extension identity and saved data. Release archives now use `saywell-0.1.0.zip`. Installing an unpacked extension from a different path can create a separate browser extension identity; changing the display name alone does not migrate data between identities.

Tooltip positioning: drag the title/handle to choose a fixed position for the current hostname; arrow keys move 10px and Shift+arrows move 40px. The small reset button returns to automatic positioning next to the editor. Positions are saved locally (up to 200 most recently moved hosts); subdomains are separate, paths/ports/protocols on the same hostname share a position. Manual placement survives result replacement, dismissal and reload. Browser resize and panel expansion keep it within the visual viewport, with internal scrolling for tall content; resizing does not overwrite the preferred relative placement. Before manual movement the tooltip continues to follow its editor. Mouse/keyboard behavior is covered in Chromium fixtures and actual extension persistence is covered by MV3 integration; touch/pen hardware, pinch zoom/mobile keyboard behavior and Edge need manual verification. Panels in embedded frames are constrained to their frame viewport, and save against that frame's hostname.

Target/parallel processing: both English and Simplified Chinese targets are implemented in all MT request contracts and the LLM prompt. Reverse-direction local models need their own browser model readiness/download. A no-key provider's earlier zh→en live success does not establish quality or availability of every reverse-direction request. MT and LLM run concurrently only when translating across languages; already-target-language polishing and Explain use LLM only. The first usable result is shown; LLM is primary, MT defaults closed once both exist. Both still require their existing separate consent/grants. Unsupported thinking switches or reasoning-only models need a compatible model/protocol or an explicitly enabled thinking option. No guarantee of universal thinking-off exists across arbitrary compatible servers. Unknown custom endpoint Auto adds no undocumented switches; use its documented protocol selector.

Apply update: ChatGPT's plain ProseMirror and x.com's Draft.js structures are represented by local fixtures; anonymous live checks did not expose an editable ChatGPT/x.com composer. Full authenticated-site testing remains manual. The public Baidu composer currently uses Slate; an explicit disposable probe (`scripts/probe-baidu-editor.mjs`) verifies Apply survives a subsequent model edit with fixed synthetic input and network blocked before typing. Real OS IME and site/model variations remain separate release checks. Rich formatting, mentions, code blocks, embeds and editor rejection continue to require Copy.

MiMo and SiliconFlow: presets and request contracts are automatically tested with synthetic credentials/responses. Browser tests cover endpoint selection, bilingual hints, complete model ID persistence, key-field clearing and mobile layout. Manual validation still required: enter your own key/model, authorize the host, and run Test Connection for each provider; verify MiMo Token Plan's dedicated endpoint separately if used. Only text-chat models producing the requested JSON are supported; image, speech, embedding and reranking models are unsuitable. Model-specific reasoning latency or token limits may need a different model or larger timeout/response budget. Both presets now send explicit thinking-off parameters by default, with an independent toggle per configuration. These keyed providers are not included in the no-key basic fallback.

- Suggestions process the entire focused editor, capped at 6,000 UTF-16 code units. No sentence slicing, selection-only processing, streaming, or AI-generated editor submission.
- MyMemory rejects over 500 UTF-8 bytes; the extension does not split drafts to evade limits. With basic fallback enabled, another authorized provider may translate the full draft. Anonymous quota can be shared by IP. No uptime or unlimited-free guarantee. Experimental Edge may stop serving anonymous requests at any time; a configured official Azure key is a separate option.
- Local model download/readiness is browser-specific; preparing in Settings does not prove it can run in every website content context. Fallback requires separate authorization.
- English counts estimate ASCII word starts, not tokenized linguistics, unique words, or final document length. Edits/deletions/pasted prefixes and host editor transformations can affect estimates. Manual paste from AI tools is categorized as paste.
- Simple field replacement is whole-field and best effort. Plain editors support undo where browser insertText does; native input replacement does not guarantee host undo-stack integration. Complex frameworks use Copy.
- Pending metrics may be lost on abrupt browser/tab termination. Analytics and saved vocabulary use local storage, not sync, and do not follow users across devices.
- Automatic errors are rate-limited in the UI; manual requests reveal errors. Background provider requests already sent cannot be recalled when a user revokes consent or edits a draft.
- A provider can ignore instructions or return poor quality. JSON validation prevents executable output; it does not establish translation correctness or protect against every semantic prompt injection.
- Browser may retain Chromium origin permissions after an application-level Revoke/Remove. Saywell's separate consent and site policy still stop its processing; use browser extension settings to remove the underlying host grant.
