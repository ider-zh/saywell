# 输入性能与回归预算（2026-10-22）

这次审查针对输入事件、练习 diff 和浮窗定位。测量使用固定合成文本、独立 Chromium 测试配置与模拟服务，不采集用户输入、真实密钥或线上接口时延。

## 审查发现与修复

| 问题 | 修复与验证 |
| --- | --- |
| 每次按键把整段前后文本展开为字符数组，英文统计再扫描全文前缀 | 使用原生前缀检查与索引切片，英文词边界只检查末尾两个代码单元。随机 Unicode/孤立代理字符与旧算法对照，保留码点语义。删除、撤销、替换及已知粘贴直接走相应分支。 |
| 练习 diff 的动态规划每个单元重复 Unicode 归一化和正则 | 缓存目标字符分类，每次尝试仅分类输入一次；正确 ASCII 大小写前缀走线性路径。保留 200,000 单元上限和长输入的有界匹配。 |
| 练习框 input 内同步 diff 并重建节点 | 每帧至多计算一次，复用高亮节点；关闭即取消回调，IME 候选阶段保留原始输入。 |
| 滚动重复测量布局、移除浮窗后才读取富文本 | 被动滚动/窗口监听在一帧合并定位；先读编辑器再移除浮窗；无变化不写样式。关闭统计与自动建议时跳过编辑器读取，手动入口继续可用。 |
| Slate 的 beforeinput/input 两次延迟回调互相取消建议 | 未变化的后续回调在取消定时器前返回；用阻止原生输入的 Slate 合成模型回归验证。 |

## 测量快照

同一开发机分别运行隔离基线与优化版本。数值是中位数，单位 ms；浏览器仅测 Saywell 注册的 beforeinput/input 处理函数，不能等同于整页的按键到绘制耗时。

| 合成场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 60,000 字符统计，末尾输入 | 4.41 | 0.052 |
| 600,000 字符统计，末尾输入 | 46.63 | 0.473 |
| 423 字符练习，大小写差异 | 65.82 | 0.383 |
| 浏览器普通输入框 60,000 字符 input，CPU 4 倍减速 | 12.0 | 1.3 |
| 浏览器富文本 60,000 字符 input，CPU 4 倍减速 | 11.4 | 1.1 |

这些是合成场景的一次测量快照，机器负载会影响结果。正常建议仍有 6,000 UTF-16 代码单元上限；更长的文档只测试本地输入统计。真实 Windows IME、已登录网站、扩展叠加和 Edge 仍需手动验收。

复测命令：先 `npm run build`，再运行 `node scripts/benchmark-input.mjs current` 与 `node scripts/benchmark-browser-input.mjs current`；输出在 `test-results/`。已有兼容 Chromium 可用 `INPUT_COACH_BROWSER` 指定。

## 自动失败的性能测试

`npm run check` 包含以下固定预算，超限即失败。核心计时在功能单测结束后独立运行，避免并行测试进程争用 CPU 导致不稳定；用 `npm run test:performance` 可单独执行。预算定义在 `tests/performance-budgets.js`，调整必须提供测量依据，不支持 CI 环境变量绕过。

| 指标 | 预算 |
| --- | ---: |
| 60,000 字符统计中位数 | ≤ 2 ms |
| 600,000 字符统计中位数 | ≤ 8 ms |
| 423 字符大小写/一般字符修改 diff 中位数（分别测试） | ≤ 12 ms |
| 浏览器 beforeinput / input 中位数，CPU 4 倍减速 | ≤ 4 / 8 ms |
| 浏览器 input P95，CPU 4 倍减速 | ≤ 32 ms |
| 浏览器 beforeinput + input 中位数，CPU 4 倍减速 | ≤ 10 ms |
| 输入处理函数内同步调用 getBoundingClientRect | 0 次 |
| 80 次连续滚动，圆环编辑器布局读取 | 同步 0 次，下一帧 1 次 |
| 80 次连续滚动，浮窗 host 布局读取 | 同步 0 次，下一帧最多 2 次 |
| 20 次连续练习 input | 同步不计算/绘制 diff，下一帧展示最后输入 |

核心每项预热 5 次、采样 25 次，保存中位数、P95、预算。浏览器覆盖普通/富文本 60,000 字符统计，以及 5,000 字符、启用自动建议/LLM 的圆环调度路径，每种使用 34 个真实按键事件。核心数据写入 `performance-results/core.json`；浏览器数据作为 `input-latency-budgets.json` 附件进入报告。Actions 将这些数据、截图和报告作为 `browser-test-evidence` 保留 7 天，便于比较回退。

## 轻量进度圆环

24px 圆环显示下一次翻译、润色或解释；句末沿用已配置 debounce，其余输入额外等待 600 ms。圆环 DOM 和几何读取在下一帧执行；进度使用浏览器动画，无 JavaScript 逐帧循环或轮询。触发时换为等待状态；MT/LLM 仍独立并行，首个可用结果返回后以 transform/opacity 动画展开浮窗。后到的 LLM 保持主结果，MT 默认折叠。

输入法 compositionstart 取消触发定时器并冻结现有圆环；候选输入不重启进度，也不接受旧结果。compositionend 等编辑器提交后，以最终文本重新计时。继续编辑、Escape、焦点离开、暂停、关闭功能、权限/网站策略变化均取消旧状态。圆环不获取焦点、不拦截点击，不存储位置之外的新数据。自动定位选择编辑器外的可见区域；没有 24px 空间时隐藏圆环。手动位置若会覆盖当前输入框，圆环临时采用安全位置，保留用户原有位置记忆。窗口、滚动与 visualViewport 变化合并到一帧处理；减少动态效果偏好关闭倒计时与展开动画。

测试覆盖双通道两种返回顺序、候选暂停、迟到结果、取消、窗口缩小、全屏输入框避让及滚动合并；截图使用合成页面。圆环仅表示本地触发倒计时和等待状态，不估计服务端完成百分比。所有请求继续受原有站点权限、服务同意和端点权限约束。
